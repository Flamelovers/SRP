# SRP：PokeMMO 画面识别原型

目标是从截图或屏幕画面自动识别精灵，无须每场手动输入名称。第一版提供指定区域裁剪、OCR 名称匹配和像素头像模板匹配。当前尚未验证实际游戏画面，不包含可用于实战的对战模拟器或训练结果。

## 安装和运行

Python 3.10+：`pip install -r requirements.txt`。另需安装 Tesseract OCR，中文界面需要 chi_sim 语言包，确保 tesseract 在 PATH。

1. `python -m srp capture --output frame.png` 截取本机屏幕。也可直接使用截图。捕获需要本机桌面及录屏权限，云端不能直接捕获手机屏幕。
2. 编辑 `config/layout.json`：各区域 `[x,y,width,height]` 相对完整截图，示例坐标必须根据实际画面修改。
3. 在 `assets/templates/物种标准名/` 放该物种的像素头像 PNG，每物种可放多张。模板和截图必须属于同一种视角；项目不包含游戏素材。
4. `config/names.json` 是物种及中文英文别名词典，示例只覆盖四种，扩展后才可识别更多物种；不是每场手动输入精灵。
5. `python -m srp recognize frame.png --output state.json`。输出 OCR 原文、图像候选及启发式相似度、冲突和未知值。相似度不是校准概率。名称被改成昵称、遮挡、缩放或缺少匹配模板时可能无法识别。
6. `python -m srp evaluate state.json` 展示候选行动接口；尚未实现招式识别及规则，缺少可用招式时会停止，不会虚构推荐。

## 四层边界和实施顺序

1. **截图识别**：截图/本机屏幕采集、布局裁剪、OCR、头像匹配。先收集实际队伍预览、战斗和招式界面截图，标注精灵和位置，测量 top-1/top-3、未知拒识与耗时；再做自动窗口定位、HP 与招式识别。
2. **状态结构化**：保留来源、原文、候选、未知与冲突；跨帧追踪双方精灵、HP、状态、可见招式，隐藏信息不能当作已知。
3. **候选行动**：根据画面观察到的招式、PP、替换名单和规则生成合法行动；未知不得默认为不存在或可用。
4. **本地模拟评估**：接入本地物种/招式数据及模拟引擎，逐项核对 PokeMMO 的伤害、速度、状态和规则差异，处理对手隐藏信息。之后才开展此前计划的 10000 场训练与独立 1000 场评估，训练与评估使用不重叠随机种子。通用模拟器的结果不等于 PokeMMO 实测胜率。

本项目不依赖官方接口，也不自动操作游戏。`python -m unittest discover -s tests` 运行基本测试。截图可能包含个人信息，分享前自行检查。
